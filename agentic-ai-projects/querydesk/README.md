# QueryDesk

### Agentic Data Analyst

A full stack data analysis application that lets a tool-using AI agent inspect a CSV dataset, execute read-only SQL, recover from query errors, and present results with charts and an inspectable audit trail.

## What it does

- CSV upload with schema inference, normalized headers, and preservation of leading-zero identifiers.
- An iterative tool-calling agent with inspect_dataset and run_sql tools.
- SQLGlot statement validation, SQLite read-only connections, an authorizer, function restrictions, query timeout, and bounded result sets.
- Follow-up question context, visible tool activity, query history, automatic bar charts, and CSV export.

## Agent workflow

Question → inspect_dataset → run_sql → error feedback / query correction → validated result → chart + SQL + audit record

The agent has a finite tool-call and iteration budget. Tool errors are returned as observations so the model can correct its next action. The browser shows tool names, outcomes, and summaries, not hidden model reasoning.

## Run locally

Requires Python 3.12 and Ollama. Download the model before the first run:

```bash
ollama pull qwen3:8b
```

Install and start from this repository:

```bash
python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000. API documentation is at http://127.0.0.1:8000/docs.

1. Open the application and click **Load sample sales data**.
2. Ask “Which region generated the most revenue?”
3. Expand **Agent tool activity** and **Inspect the SQL**.
4. Ask a follow-up, then export the computed result.

## Configuration

Set environment variables before starting Uvicorn. For example, macOS/Linux uses `export CHAT_MODEL=qwen3:8b`; PowerShell uses `$env:CHAT_MODEL="qwen3:8b"`.

| Variable | Default | Purpose |
| --- | --- | --- |
| CHAT_MODEL | qwen3:8b | Tool-calling chat model |
| OLLAMA_URL | http://127.0.0.1:11434 | Your Ollama server |
| DATA_DIR | data | Persistent application data |

Inference calls go to OLLAMA_URL. With the default local URL, the application does not send prompts to a hosted model provider. Uploaded data is stored in DATA_DIR and is not committed to Git. The included sample data is fictional.

## Tests

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Coverage includes CSV validation, schema inference, actual SQL aggregation, CTE handling, forbidden SQL, table isolation, result limits, agent query-error recovery, tool budgets, and upload → ask → history → export API integration.

Agent/API integration tests use scripted model responses and real application logic, SQLite, parsing, and validation. They verify orchestration and error handling; they are not a benchmark of an installed model’s answer quality. Live model inference needs your own running Ollama instance. GitHub Actions runs the same test suite on pushes and pull requests.

## Design decisions

The model can propose queries but cannot bypass the execution layer. The application, not the model, decides which tools exist and whether SQL is allowed. Query results come from SQLite rather than text generated by the model. Final prose describes the computation; the result table and SQL remain the source of truth.

## Containers

A Dockerfile and compose.yaml are included. `docker compose up --build` exposes the app on 127.0.0.1:8000 and persists DATA_DIR in a named volume. The configured host Ollama URL must be reachable from inside the container; adjust OLLAMA_URL for your Docker network. Native Python is the simplest local setup. Container builds were not exercised in the build environment.

## Scope

CSV only; one imported dataset per query. Numeric inference deliberately avoids currency formatting and unit conversion. An allowed query can still answer the wrong business question, so inspect the SQL. This is a single-user local workspace; add authentication and per-user data isolation before network deployment.
